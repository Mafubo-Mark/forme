# 给云端开发同事的改造任务书

更新：2026-10-05。可直接转发给负责云服务器的同事或 Claude Code。**本文件是工作要求，不表示云端后端已经完成。**

## 项目目标

用户前端须能 **24 小时接收登录、视频上传、设计提交和进度查询**。COLMAP、混元 3D、WorkBuddy/Blender 的建模处理**允许排队**，开发电脑离线时应显示“等待处理”，不能让用户的登录或上传一起中断。

请按“**云端接收和持久保存 + 本机工作器主动领取任务**”实施。现有 SSH 反向隧道只用于短期联调，不作为正式上线方案。若将来要求建模也持续运行，再增加云端工作器；本次不要将“电脑必须一直开机”写成生产依赖。

## 云端必须完成的工作

### 1. 常驻客户 API

把登录、会话、模板列表、上传初始化/完成、设计提交、任务列表和详情迁到云端常驻服务。保持前端同源 `/api/customer/*` 和 `/api/uploads/*` 路径，或同时提交经过验证的前端适配。API 进程重启后，已创建的会话、上传和任务不能丢失。

当前前端依赖的主要接口：

| 请求 | 当前用途 |
| --- | --- |
| `POST /api/customer/login`、`GET /api/customer/session`、`POST /api/customer/logout` | 共享密钥登录与会话 |
| `GET /api/customer/templates` | 获取七款可选模板 ID |
| `POST /api/uploads/init`、`PUT /api/uploads/{id}/content`、`POST /api/uploads/{id}/complete` | MP4/MOV/WebM 视频上传，最大 512 MiB |
| `POST /api/customer/submissions`、`GET /api/customer/submissions`、`GET /api/customer/submissions/{id}` | 保存模板、颜色、材料并查看任务 |
| `PUT /api/customer/submissions/{id}/inspiration-image` | 可选灵感图片，最大 10 MiB |

当前 `dist/js/create-workflow.js` 会使用 `init` 返回的 `uploadUrl` 直接 `PUT`，并发送同源 Cookie。如改为对象存储直传，请同步修改浏览器上传逻辑、短期授权、跨域设置和完成确认；不要把对象存储长期凭据写入 JavaScript。视频写入后须检查实际大小、文件类型和完整性，再允许建立 submission。

### 2. 持久数据库、私有文件存储和任务队列

- 会话、上传元数据、任务、状态事件和工作器租约存入有备份的云端数据库；从当前 SQLite 迁移时保留唯一约束、状态条件更新和客户任务归属。先确定是否迁移旧测试任务；**不得未经负责人同意复制旧视频和私人数据**。
- 视频、灵感图及生成结果放私有对象存储，不放公开网站目录。上传可通过短期授权直传或云端流式转存；大文件上传失败须可明确重试，且不能生成假成功任务。
- 提交后将处理任务写入**持久队列**。API 应快速返回“已接收/排队中”；队列在 API 或工作器重启后仍保留任务。使用任务 ID、输入 SHA-256 和幂等状态转换控制重试，避免重复调用可能计费的混元接口。
- 用户查询返回真实状态：`received`、`queued`、`processing`、`needs_review`、`failed` 等。状态名称可以调整，但前后端必须使用同一契约；不能把“上传成功”显示成“模型生成成功”。

### 3. 本机工作器与后台分离

- 开发电脑上的计算工作器**主动通过 HTTPS**连接云端领取任务，下载授权视频，完成阶段后上传结果和状态；云服务器不需要通过 SSH 反向隧道访问 Mac。工作器离线时任务留在队列，用户仍可登录、上传和查看等待状态。
- 给工作器单独的最小权限身份。管理接口、任务领取接口及资源下载必须鉴权、记录操作，且不与客户共享密钥混用。
- 操作面板与用户页面保持独立。可以设独立管理域名并限制 VPN/私有网络访问，或采用同等受限方式；公开用户站点的 `/operator/` 和 `/api/internal/*` 应不可访问。操作员须能查看云端任务，并在本机工作器恢复后继续审核。
- 当前 COLMAP 点云停在尺标定尺度复核；混元自动队列和 WorkBuddy/Blender 制造成品链仍未完成。本次基础设施改造不应把这些阶段伪装为已自动贯通。

### 4. 运行与安全

配置 HTTPS、服务自动重启、健康检查、容量监控、失败告警、数据库和对象存储备份及恢复演练。密钥通过云端密钥管理或受限环境配置提供；仓库、静态前端、日志和错误响应中都不能出现客户密钥、工作器凭据、腾讯云/视觉 API 密钥或原视频内容。需要明确上传资料的访问权限、保留期限和删除流程。

当前共享密钥登录只按浏览器会话归属任务，退出后再次登录不能自动找回旧任务。请在上线方案中单列**用户身份与任务找回**的改造及迁移方式；在解决前不要宣称它已是正式多用户账户系统。

## 分阶段交付与验收

1. **先交付设计和依赖清单**：实际云资源、域名、容量/费用估算、后端代码获取方式、数据库/对象存储/队列选择、管理员入口、备份方式及前端接口变更。标出需要项目负责人提供的信息，不要自行发明凭据。
2. **在测试环境完成接收链**：从云站点登录、上传并提交一段获授权的视频；云端记录同一 submission ID、模板、颜色、SHA-256 和状态。错误密钥、超限视频、断线及重复完成请求应有明确结果。
3. **关闭 Mac 做关键故障测试**：浏览器仍能登录、上传新视频、查询旧任务和“等待处理”状态；无需本机 SSH 隧道。重启云端 API 后，任务和文件仍在。
4. **恢复本机工作器**：它领取排队任务、只处理一次、回写可见进度；故意中断后能重试或进入明确失败态。若暂未交付工作器协议，至少证明队列和任务状态可持久保存，并明确此项未完成。
5. **权限与恢复检查**：公网 `/operator/`、`/api/internal/*` 不可访问；非本人不能读视频和任务；备份恢复至少演练一次；提供部署脚本、环境变量模板（无真实密钥）、接口变更说明和回滚步骤。

**完成定义：** Mac 关机时用户端仍可完成登录、上传、提交和进度查询；Mac 开机后排队任务能继续处理。这两项都由实际测试记录证明后，才能把云端接收链称为贯通。
