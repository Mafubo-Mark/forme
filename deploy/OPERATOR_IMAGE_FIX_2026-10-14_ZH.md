## 修正内容

原拍摄复核图使用整组 `Promise.all`，任意请求卡住会拖住整个画廊及后续任务刷新。改为逐图显示，并统一处理候选图、复核图、混元预览及标尺图：

- 每次最多 3 条图片传输，20 秒超时；单张错误不会阻塞其他图片。
- 本机请求使用页内 Bearer，云端请求沿用同源管理员 Cookie；令牌不放进图片 URL。
- 401 明确提示重新登录；其他故障给出状态及“重试此图”。
- 同一任务的图片在页内存复用，避免每 3 秒轮询重新下载；重新打开任务时清空缓存，切换任务时取消旧请求并回收对象 URL。

本机已应用的文件在 `worker/local-backend-overlay/operator/`，包括 `index.html`、`js/app.js`、新增的 `js/media-loader.js` 和 `css/app.css`。一并覆盖本机后端对应文件即可；无需更改数据库、密钥或鉴权。

## 云端验收

远程面板通常直接代理 Mac 的上述静态资源，无需重启正在运行的点云任务。刷新云端远程面板应取得新版 HTML 和两个 JS 文件。若服务器另外缓存了操作面板副本，则同步这些文件并刷新缓存。

1. 在 `/admin` 登录，打开“本机建模工作流”，重新选择任务。
2. 检查候选帧与拍摄复核帧逐张出现；确认浏览器图片 `naturalWidth > 0`。
3. 如果出现错误提示，记录 HTTP 状态：401 为会话过期，404 为文件或路由缺失，503 为 Mac／隧道不可用，超时为传输未完成。
4. 未登录和普通客户仍应得到 401，不得通过关闭鉴权修复图片。

Node 的 5 项图片加载测试已通过，覆盖并发限制、单图失败、会话失效、超时后队列恢复、任务切换的资源回收。本机媒体与视角相关的 3 项 Python 集成测试也已通过。
